# Tennis Tournament Telegram Bot

Telegram-бот для регистрации игроков, ввода результатов и таблицы турнира.
Для постоянной работы используется Railway worker и PostgreSQL.

## Локальная проверка

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
# заполните .env
python migrate.py
python -m unittest discover -s tests
python bot.py
```

## Переменные окружения

```env
BOT_TOKEN=токен_от_BotFather
DATABASE_URL=строка_подключения_PostgreSQL
ALLOWED_JUDGES=123456789,987654321
```

`BOT_TOKEN` нужен для подключения к Telegram. `DATABASE_URL` указывает на PostgreSQL;
если он пустой, используется локальный SQLite. `ALLOWED_JUDGES` содержит Telegram ID
судей через запятую.

## Как добавить судью

1. Судья получает свой Telegram ID через `@userinfobot` или другой надежный бот-идентификатор.
2. В Railway откройте проект, сервис `Tennis_Bot` и раздел **Variables**.
3. Создайте или измените переменную:

```text
ALLOWED_JUDGES=123456789,987654321
```

4. Сохраните переменную и выполните **Redeploy**.
5. Судья открывает Telegram-бота и отправляет `/start`.

ID указываются только числами, без `@`, пробелов и кавычек. Для удаления судьи
уберите его ID из списка и снова выполните redeploy. Пустой список запрещает
защищенные команды всем пользователям.

## Команды

- `/start` — открыть меню
- `/register_player Имя Игрока` — зарегистрировать игрока
- `/players` — список игроков
- `/start_tournament` — начать турнир
- `/finish_tournament` — завершить турнир и запретить новые результаты
- `/result "Имя Победителя" "Имя Проигравшего" 6:3 7:5` — добавить результат
- `/table` — турнирная таблица
- `/stats` — статистика
- `/cancel` — отменить ввод
- `/delete_all_players CONFIRM` — удалить всех участников и результаты

Результаты, запуск, завершение и очистка доступны только судьям из `ALLOWED_JUDGES`.
Счет принимает сеты формата `6:0`–`6:4`, `7:5`, `7:6`; победитель должен выиграть
большинство указанных сетов.

## Рабочий сценарий турнира

1. Зарегистрируйте минимум двух игроков через `/register_player Имя Игрока`.
2. Судья запускает `/start_tournament`.
3. Судья выбирает **Результат матча**, игроков и отправляет счет, например `6:3 7:5`.
4. Таблица доступна через `/table`, статистика через `/stats`.
5. После окончания судья отправляет `/finish_tournament`.

## Очистка турнира

Команда ниже необратимо удаляет всех игроков, матчи и статистику, затем сбрасывает
турнир в состояние `inactive`:

```text
/delete_all_players CONFIRM
```

Без точного слова `CONFIRM` данные не удаляются.

## Онлайн через Railway

1. Создайте бота через `@BotFather`.
2. В Railway создайте проект и добавьте сервис `Tennis_Bot` из GitHub-репозитория.
3. Добавьте PostgreSQL-сервис и подключите его к сервису бота.
4. В `Tennis_Bot` → **Variables** добавьте:

```text
BOT_TOKEN=токен_от_BotFather
DATABASE_URL=строка_подключения_Railway_Postgres
ALLOWED_JUDGES=telegram_id_судьи
```

5. В **Settings** проверьте команду запуска:

```text
python bot.py
```

6. Выполните **Redeploy** и проверьте **Deploy Logs**. Сервис должен оставаться
в состоянии `Online` без повторяющихся ошибок.

Railway использует `Procfile` с worker-командой и не требует HTTP-порта: бот работает
через Telegram long polling. После push в подключенную ветку Railway обычно создает
новый deployment автоматически.

## Безопасность

Не публикуйте `.env`, токен бота или пароль PostgreSQL в GitHub. SQLite подходит только
для локальной проверки; для онлайн-работы используйте PostgreSQL. Бесплатные планы
Railway могут иметь ограничения, поэтому проверяйте состояние сервиса и сохраняйте
резервные копии важных данных.
